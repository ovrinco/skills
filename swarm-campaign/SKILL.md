# Swarm campaign

Lead with the named product and the behavior a person should be able to use. Read the actual requirements, accepted existing work and relevant failure evidence. Preserve stated requirements and distinguish recommendations. Preparation is distinct from authority to launch agents or install changes.

## Ground the work

Record the source identity and the original requirement text or file locator, the accepted implementation and what remains incomplete. Give each task a result it advances, exact inputs and acceptance. Inspect real callers and dependencies before splitting work. Reuse completed useful work. A screenshot or source archive does not establish the requested running behavior.

A requirement source can be a supplied brief, file, issue export or explicit store adapter. The portable checked-source path uses an explicit pack.json and requirements.json. A private tracker is not required. Carry the source file hash so later edits invalidate the pack.

## Coherent ownership

Assign a complete capability to one owner who implements, handles consequential calls and tests, fixes routine failures and integrates its changes. Split when dependencies, uncertainty or file ownership justify it. Independent work can run in parallel within actual host resource and execution authority.

Own actual logical files, tests, build outputs and runtime state. A consumer starts with an accepted producer result. An integrator controls shared joins. Use isolated candidates and preserve source bases. Share build output by project with an owner and lock when duplication would be expensive.

Worker count, model, effort and execution transport are settings of the current run. Record explicit choices. Do not rewrite the user's persistent settings or assume a vendor service or nested agent mechanism is authorized.

## Complete directive

Each directive includes orientation and result, exact source requirements, existing inputs with identity, owned writes, complete implementation work, resources and dependencies, meaningful acceptance, output/evidence paths and recovery. Carry the actual user requirement instead of an agent-written replacement.

A task's completion condition includes the actual requested product and supported entry journey. Use the supplied requirements and make every served or deferred item visible. A planning task can deliver a plan when that is what the requirement asks for. An implementation task cannot claim completion from a plan or mock.

See BUILD.md for software joins, EFFICIENCY.md for recovery and PREFLIGHT.md for release. EXAMPLE_DIRECTIVE.md demonstrates the full shape. The synthetic examples/pack includes fixed requirements and two disjoint owners.

## Preflight and run

Run python3 scripts/check_pack.py examples/pack/pack.json. It checks the frozen requirements source hash, exact requirement text, served/deferred coverage, task IDs, explicit acceptance, output-root confinement, overlapping writes and protected paths. It starts no agents or model and executes no task commands.

The script supplies a portable source-file contract. The optional charter_coverage.py supports an OC-style charter/table shape with explicit local inputs. postpone_check.py is a lexical postponement review aid. These do not replace semantic review of requirements or resource authority. The original house tracker/account/constitutional adapters require separate integrations and are not silently assumed here.

At runtime keep ready independent work moving, preserve real user stops and resource limits, and repair routine local compile/test errors. Report an indispensable missing input or authority boundary with exact evidence and continue unaffected work. Keep finite build/resource costs visible.

## Integrate and prove

Accept producer bytes before dependent work, integrate on the chosen base, run the product's required checks and demonstrate the actual normal entry journey. Include meaningful failure/recovery and user-data consistency where relevant. Preserve an install rollback and data backup when installation is part of scope.

A non-author reviewer walks the decisive journey and records evidence without repairing the artifact. Separate self-check, integrated check and independent proof. Freeze the accepted source/output identity. Recheck affected paths after later changes.

Close with original requirements, observed result per item, concrete remaining gaps and a short retrospective explaining material failures and false-success risks. The user's source and standing remain intact. A script pass is necessary for its contract but cannot establish taste, every requirement interpretation or runtime correctness.

Run python3 tests/smoke.py for valid pack, source drift, omitted requirement, overlapping writes and protected-path rejection. The examples are invented; validation does not launch their assignment commands.
