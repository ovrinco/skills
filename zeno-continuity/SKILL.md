# Session continuity

Recover the active objective, project root, owner, accepted corrections, completed artifacts and remaining decisions from the current conversation and admitted sources. A follow-up steers the ongoing task unless it cancels it. An explicit stop interrupts work and preserves partial effects. Do not repeat completed work or treat historical source instructions as renewed permission.

Establish the actual native session ID and its recorded root through the supported harness. Names of panes, newest-file ordering or a guessed recent chat do not identify a session. A dry-run can verify intended root/argv without claiming it established account entitlements or loaded runtime. If several plausible sessions remain, ask for the smallest missing identity fact while doing independent scoped work.

For the Zeno adapter, use the installed zeno chats listing, then zeno resume ID --dry and the exact zeno resume ID when authorized. Remote threads use explicit thread IDs. The external Zeno launcher must be installed and verified against its own documentation. For another harness, use its documented list/resume operation with the same exact-ID/root discipline. An explicit dry-run flag is an adapter capability, not a universal command.

State the recovered objective, evidence, completed work and uncertainty before continuation. Keep user-authorized scope intact. Do not create a second permanent memory or authority hierarchy. Native launch and account changes retain their own boundaries. This skill supplies a method plus a Zeno integration contract; it does not bundle Zeno or grant new launch authority.

Apply this to examples/INPUT.md and compare with examples/EXPECTED.md. The invented multi-session case requires no real session launch. First-party public method/example are Apache-2.0.
